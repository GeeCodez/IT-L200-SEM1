🧠 UML (1 line)

UML (Unified Modeling Language) is a visual language used to model, design, and communicate the structure and behavior of a system.

🔷 UML DIAGRAMS (ONE-LINE EACH)
🔹 STRUCTURAL (WHAT EXISTS)
Class Diagram: Shows the structure of a system with classes, attributes, methods, and relationships.
Object Diagram: Shows instances of classes and their relationships at a specific point in time.
Component Diagram: Shows system components/modules and how they interact.
Deployment Diagram: Shows how software is deployed on hardware (nodes/servers).
Package Diagram: Shows grouping of elements and dependencies between packages.
Composite Structure Diagram: Shows the internal structure of a class/component and how parts interact.
🔹 BEHAVIORAL (WHAT HAPPENS)
Use Case Diagram: Shows system functionality and interaction between users (actors) and the system.
Activity Diagram: Shows the workflow or step-by-step flow of activities in a system.
Sequence Diagram: Shows interaction between objects in time order (who talks first, next, etc.).
State Machine Diagram: Shows states of an object and transitions between those states.
Communication Diagram: Shows interaction between objects focusing on relationships rather than time.
Interaction Overview Diagram: Shows a high-level flow of multiple interactions in a system.
🧠 OBJECT-ORIENTED ANALYSIS (OOA)
✅ Definition (1 line)

Object-Oriented Analysis (OOA) is the process of analyzing system requirements using objects, classes, and their relationships.

🔥 Characteristics of OOA (you already have some — refined)
Use Case Driven: Development is based on user requirements (use cases).
Architecture-Centric: Focuses on defining a strong system structure/architecture.
Iterative and Incremental: System is developed in repeated cycles with gradual improvements.
🔁 UNIFIED MODELING PROCESS (UP)
✅ Definition (1 line)

The Unified Process (UP) is an iterative software development framework that uses UML to guide system development.

🔥 PHASES OF UNIFIED PROCESS (ONE LINE EACH)
Inception: Define project scope, goals, and feasibility.
Elaboration: Analyze requirements and design system architecture.
Construction: Build and develop the actual system.
Transition: Deploy system to users and perform testing/training.
⚙️ ENGINEERING WORKFLOWS (ONE LINE EACH)
Business Modeling: Understand business processes and environment.
Requirements: Gather and define what the system should do.
Analysis & Design: Convert requirements into system design (models/architecture).
Implementation: Write code and build the system.
Testing: Verify system works correctly and meets requirements.
Deployment: Release system to users and production environment.
👥 PROJECT TEAM ROLES (ONE LINE EACH)
System Analyst: Translates user requirements into system specifications.
Business Analyst: Identifies business needs and ensures system solves business problems.
Infrastructure Analyst: Designs and manages hardware, networks, and system environment.
Change Management Analyst: Handles user adoption, training, and system transition.
Project Manager: Plans, coordinates, and ensures project is completed on time, scope, and budget.
